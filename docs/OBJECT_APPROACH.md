# 去货架旁边：临时安全接近位置

2026-10-20当前：bringup的DeepSeek入口默认原生工具闭环，支持环境查询、多物体串行接近和真实结果反馈；不再限制一句话一个物体。旧JSON入口可用agent_tools=false回退，原rules/非AI入口保留。临时接近的固定物体/几何限制仍在；真实API及机器狗实走待验收。见[工具模式说明](AI_TOOL_AGENT.md)。以下单动作/不支持多物体描述是前阶段记录。

2026-10-20货架编号已自动配置：`shelf_1`～`shelf_17` 对应“货架1”～“货架17”，支持“1号货架”“一号货架”等别名。当前场景标注已保存，之后无需手动定义货架A；直接输入 `去三号货架旁边` 或 `去17号货架旁边`，导航仍需先显式开启。内部Gazebo模型名不改，原自定义名字可作为别名继续使用。

## 当前能力（2026-10-20）

在现有语义目录之上新增单物体接近任务：通过模型原名、中文名或别名定位对象，读取已知场景SDF碰撞体，
生成临时候选站立位置，使用当前Nav2全局障碍图与实际保护轮廓筛选，再请求真实Smac Lattice验证可达性。
选择通过验证的位置后，以原 `/navigate_task` 提交坐标；整个过程不写入Places/语义地点文件、不修改地图或控制参数。

当前先支持默认仓库中17个货架等原场景固定刚性物体。读取的是Gazebo真值及场景定义，不是雷达/相机语义识别。
“检查”暂指到对象附近并面向物体，不包含图像拍摄、设备故障识别或检查结果判断。

## 启动与操作

先退出旧console/bringup；构建安装已完成。终端1：

```bash
source /opt/ros/jazzy/setup.bash
source /home/ma/lite3_ws/install/setup.bash
ros2 launch lite3_navigation bringup.launch.py ai_control:=true language_mode:=deepseek
```

等待READY及后台就绪后，终端2：

```bash
source /opt/ros/jazzy/setup.bash
source /home/ma/lite3_ws/install/setup.bash
ros2 run lite3_navigation ai_console
```

无需API的固定句式验证，把终端1最后一项换成 `language_mode:=rules`。
两种模式都可以使用以下内容；输入在ai_console内，不是shell命令：

```text
查询物体 shelf_1
标注物体 shelf_1 名称=货架A 类别=货架 别名=一号货架
开启导航
去货架A旁边
```

已有货架A标注时不必重复标注。查询/标注不运动；开启导航只允许后续任务；最后一条会在验证通过后启动运动。
默认导航总开关关闭；必须等开启成功再发送任务。本功能不会自行解锁停止保护。

预期先显示“计算临时接近位置”，然后显示候选验证，成功时显示“已选临时接近点”及坐标，再进入原导航任务。
无需自己存点1，也无需将选出的坐标复制到另一个命令中。
默认在货架四侧尝试；按候选位置到当前机器狗的直线距离由近到远，选首个通过规划验证的位置。
不保证路线全局最短，也不会让模型凭感觉编造目标坐标。

明确方位/距离的固定句式：

```text
去一号货架南侧 距离=0.5
去shelf_2旁边
去shelf_2北侧
```

东/北对应地图+X/+Y，西/南对应-X/-Y，不随相机或机器狗朝向改变。
默认距离0.4m，允许0.15～1.5m，含义是导航保护轮廓前缘与物体外包边界的期望间隔；
几何计算额外留5cm离散误差余量，不是机器人中心到货架中心的距离。
默认保护半长/半宽来自实际costmap参数footprint+padding，当前约0.47m/0.25m；不另行缩小机器人。
指定侧无可站立/可达位置则拒绝，不偷偷改到另一侧。

DeepSeek正式入口还可尝试：“请带我去一号货架旁边”“到货架A南侧停下，离边缘半米”。
模型输出白名单approach任务，只含对象、方位、间距，坐标仍由本机计算。
真实在线措辞待用户验收，本次自动测试未使用真实API。单目标的 `去货架A` 若解析为环境物体，也会转为接近任务；
原已保存地点名优先保持原意，地点导航与返回原点不变。

途中停止：输入 `停止`；状态：输入 `查询状态`，准备阶段会补充“正在验证物体临时接近点”。
退出：console输入“退出”或Ctrl+C，等待停止确认，再在bringup终端Ctrl+C。
停止/会话断线会取消候选规划或原导航，迟到结果不执行。

## 程序如何计算

1. 本机用语义目录唯一ID解析物体，要求当前场景中真实存在且无倾斜。核对world文件仍与启动时绑定一致。
2. 从原场景SDF读取碰撞几何，合并为模型局部XY外包矩形；支持无roll/pitch、无relative_to、非关节/非嵌套的固定模型，
   几何为box/cylinder/sphere/cone。读取collision而不是visual。外包矩形是保守近似，可能拒绝实际可穿过的空洞。
3. 按当前Gazebo模型位置/yaw将矩形放到世界系。四面各取中间及四分之一/四分之三位置，共最多12个候选。
   机器狗朝向该面的内法线，中心偏移为保护半长+期望间距+5cm。
4. 从 `/global_costmap/global_costmap/get_parameters` 读取footprint、padding、global_frame，
   从 `/global_costmap/get_costmap` 取得完整原始uint8障碍地图；要求map坐标系和2.5秒内的更新。
   检查完整机器人矩形内部、边缘和旋转角落与致命/未知栅格的相交，中心落入inscribed代价也拒绝。
   普通膨胀代价不是全部致命，仍由原规划器权衡。
5. 用 `/planner_server/get_parameters` 确认GridBased是Smac Lattice；按距离顺序向原
   `/compute_path_to_pose` 发送目标，`use_start=false`始终从实际机器人位置规划。
   不可达候选可换下一个；起点占用、TF/规划服务异常等直接报告，不盲目反复尝试。
6. 校验规划状态/错误码、路径frame和有效位姿、终点位置/朝向及当前起点是否变化；
   重新获取新costmap确认站立点仍空闲、物体实例与位置未变化，然后发送原NavigateTask。
   原任务节点会再次规划并执行；候选ComputePath不直接交给电机或FollowPath。

候选验证最多35实际秒，单个规划响应最多6秒；超时不退回不验证的坐标。
停止/断线/代际变化会废弃旧回调并定向取消旧规划句柄，不取消其他客户端的整个Action服务。
验证和执行期间物体实例改变、移位超过3cm、朝向改变超过2度、倾斜或实时目录不可用，会拒绝/停止本次临时任务。
这是固定物体接近，不是追踪移动物体；没有自动跟着移动目标重新生成追逐任务。

## 约束、兼容与数据

- 本版本只用原world定义的固定碰撞几何；运行中新增箱子、动态/关节模型、mesh和特殊相对坐标拒绝自动接近，
  但仍正常出现在语义目录和原避障系统里。尚不支持运行中改物体碰撞尺寸、同名替换模型后继续沿用原几何。
- 固定物体在Gazebo中平移/绕Z旋转时使用实时位姿；计算中或执行中移动则取消，需要重新请求。
- 使用默认Smac Lattice；选择navfn回退时原导航仍可用，自动接近功能明确拒绝，不声称中心线规划完成了全轮廓校验。
- 当前项目map与Gazebo world对齐，其他地图变换/起伏地形暂不支持。高度方向整物体投影为保守外包范围，未推断可从高架下钻过。
- 临时坐标只存在当前交互任务内存和反馈中，结束后释放；不修改places.json/语义标注。
  已有标注、普通坐标导航、选点、键盘、Nav2控制器、RL和感知参数都保留。
- 暂不支持多物体巡检、受阻跳过、巡检访问顺序优化；一次先接近一个对象。
- 额外使用现有Nav2规划Action和读取参数/地图服务，没有新增ROS节点或自定义消息。
  不使用任意shell，不让模型改项目、改安全参数或自动开导航。

## 验证

证据见[临时物体接近验证](development_history/evidence/object_approach_2026-10-20/README.md)。
79项离线单元通过。真实Gazebo仓库＋真实Smac Lattice/全局costmap在隔离域验证候选生成、
可达性、南侧与间距、原NavigateTask目标交接和不持久化；该测试只启用静态/膨胀层、合成map发布/机器人TF，NavigateTask是替身。
另有模拟协议验证关闭导航、未知/旧地图、候选失败回退、停止/迟到接受、物体移位、错误终点、超时和失联。
未启动机器狗/RL或真实API，不能据此宣称实际走到货架或动态避障完整验收通过；需用户启动正常系统试走。
