# DeepSeek工具闭环：环境理解与多步任务

## 当前实现（2026-10-20）

原来的正式DeepSeek入口每句话只解析一个白名单JSON动作，执行端也缺少跨物体任务编排。
现在默认bringup的DeepSeek模式启用原生function/tool calling：

用户完整要求 → 模型读取结构化环境/上下文 → 选择后台工具 → 本机验证与执行 → 返回真实结果 → 模型决定下一步。

模型可以根据原始名称的含义、类别和位置理解“东墙”等对象，不要求为每种说法增加别名。
原来的货架中文编号作为辅助信息保留，不是整条指令的匹配表。
墙体原名仍为wall_east等，提供实际位置和地图坐标轴，模型可自行对应“东边那面墙”。

没有新增ROS节点：仍是lite3_interaction与ai_console；HTTP守护线程不操作ROS，主线程分发工具。
不执行模型产生的shell，不暴露读写项目、源码修改、密钥读取或任意程序执行工具。
原Gazebo选点、坐标导航、键盘、Nav2/RL和雷达链路不变。rules模式仍不调用API。

## 启动与验收

先退出旧console/bringup。本轮已构建安装。终端1：

```bash
source /opt/ros/jazzy/setup.bash
source /home/ma/lite3_ws/install/setup.bash
ros2 launch lite3_navigation bringup.launch.py ai_control:=true language_mode:=deepseek
```

终端2：

```bash
source /opt/ros/jazzy/setup.bash
source /home/ma/lite3_ws/install/setup.bash
ros2 run lite3_navigation ai_console
```

连接后应显示“DeepSeek工具模式（查询环境→调用工具→真实结果→下一步）”。
使用已有仓库外密钥配置，本轮未读密钥或替用户发真实API请求；不需要重新配置凭据。

在交互终端中先输入：

```text
开启导航
```

等待开启成功，再输入：

```text
先去东墙，再去货架1，最后回到出发的位置
```

这句话应整体提供给模型。模型可以查询目录/状态，依次选择东墙、货架1，再返回本轮指令开始位置。
每个物体的临时站立位置仍由本机读取碰撞几何、costmap和Smac验证，不存为长期检查点。
运动Action确认成功才把成功交给模型。当前子导航完成显示“当前导航步骤已完成，AI继续处理整组任务”，
模型结束本轮后显示总答复及程序产生的实际执行记录，不把第一个子任务误显示成整组结束。

还可尝试：

```text
环境里最东侧的墙是哪一面？
去那面墙旁边
再去刚才第二个地方
有哪些货架？它们在哪里？
把这些已保存地点都删掉
```

后续指代只在已有足够上下文时有确定含义；没有前文不能猜。新会话会清空记忆。
查询会调用模型或工具，不需要先开启导航；真正运动仍要求本地导航开关已开启。
最后一条删除操作只适用于用户保存地点，不删除墙、货架、启动原点或项目文件；请仅在确实想删除地点时测试。

停止/查询状态：

```text
停止
查询状态
```

这些以及“开启导航”“帮助”“确认覆盖点名”由本地优先处理，不等待模型。
新完整任务执行中暂不接受另一个自由任务；请等待或先停止。现场查询可用本地“查询状态”。
退出console输入“退出”或Ctrl+C，等停止确认后再在bringup终端Ctrl+C。

## 能力清单

| 工具 | 输入/用途 | 返回依据 |
|---|---|---|
| get_environment | 可按类别、物体/地点筛选目录 | 当前Gazebo快照及语义标注，含位置与存在状态 |
| get_object | 查询真实对象ID/名称 | 当前目录中的对象详情 |
| get_robot_state | 查询导航状态、当前位姿、原点和本轮出发位置 | 任务状态服务和有效TF |
| list_places | 查询用户保存地点 | Places真实记录 |
| approach_object | 对象、可选地图方位与间距 | 临时接近计算＋原NavigateTask实际结果 |
| navigate_to | 一个已保存点名或用户给出的绝对坐标 | 原NavigateTask实际结果 |
| return_to_start | 回本轮指令开始处 | 本轮开始时有效TF快照，不存文件 |
| return_home | 回本次启动原点 | 原启动原点，不是地图零点 |
| save_place | 当前位置/指定坐标保存地点 | 原原子持久化逻辑；覆盖仍需用户本地确认 |
| delete_places | 指定名称列表或全部删除 | 先校验所有名称存在，再一次性写入，避免只删一半 |
| annotate_object | 修改中文名、类别、别名、用途 | 原语义持久化，不修改Gazebo模型几何 |
| stop_task | 关闭导航并取消剩余任务 | 原任务与运动停止机制 |

模型没有开启导航/解除停止锁定工具，需要用户在本地明确输入“开启导航”。
它可以理解“先做A再做B”的组合，不需要为整句话提供专门规则；结构化工具参数仍需通过本机校验。
当前可串行调用多个物体接近/普通地点任务；新增箱子/动态物体/mesh接近仍沿用原几何限制。
“巡检”仍表示到点访问，尚未加入摄像头检测、设备状态判断、抓取、跳跃、SLAM或移动目标追踪。

## 环境、记忆与隐私范围

初始请求提供完整原句、当前环境对象目录、实际位置、坐标轴说明、机器人当前位置和启动原点。
可通过工具获取更新后的目录和状态。模型不直接读取SDF、PGM、原始雷达点云或整个障碍栅格。
这比旧单动作模式多发送了环境位置、机器人位置和近期工具结果；这些内容随API请求发送给DeepSeek。
API Key仅在HTTPS认证头中使用，不放入消息、工具结果、项目文件或本轮验证证据。

记忆仅在后台内存，最多保留最近3轮。保留真实工具调用/结果；较长对话按整轮压缩或移除，
不留下孤立tool_call消息。压缩保留工具名、参数和实际结果，不把失败记成成功。
不落盘完整聊天或模型回复，不构建跨用户会话记忆。当前环境及最新工具返回优先于历史记录。

## 执行与停止保障

- 所有native工具响应先整批校验，未知工具、字段、重复调用ID、重复JSON字段、非有限数和截断响应拒绝，不部分执行非法批次。
- 一批多个工具在主线程串行执行。运动工具等待实际Action结束后才执行后续工具，HTTP等待不阻塞ROS心跳/停止。
- 模型可查询、组合、解释，几何计算及运动安全仍由现有程序/Nav2负责，不能修改保护轮廓等参数强行通行。
- 任务/场景/位姿变化、停止和失联仍由原有检查负责；迟到HTTP或Action不恢复已取消任务。
- 运动失败先按原流程停止与清理，再向模型返回失败。本轮随后只能查询/解释，不能自动开启导航或执行排队运动/数据修改。
- 同名覆盖由本地明确确认；模型无法生成一个工具调用代替用户确认。
- 单组最多24次运动、32次模型请求、64次工具调用、20实际分钟；单次HTTP30秒本机期限，超过即废弃迟到结果。
  单个原NavigateTask及临时接近规划仍保留自身超时。不是无限重试或无限自主运行。
- 模型文字答复不是运动证据；最终额外显示程序根据真实工具结果生成的执行记录。

## 回退与兼容

日常命令不变，bringup新增 `agent_tools` 默认true，只在language_mode=deepseek时启用。
如需对照旧单次JSON解析：

```bash
ros2 launch lite3_navigation bringup.launch.py ai_control:=true language_mode:=deepseek agent_tools:=false
```

固定规则：`language_mode:=rules`。完全不使用AI/交互后台：按原命令启动，不加ai_control:=true。
直接手动运行interaction_backend时agent_tools参数默认false（便于独立旧入口验证）；日常bringup已传入默认true。
