## 一句话介绍

复用Lite3预训练运动策略，在ROS2 Jazzy与Gazebo Harmonic中实现已知仓库地图上的目标导航，
加入三维雷达感知、二维代价图和移动障碍避让，任务通过终端或Gazebo选点交互。

## 可展示成果

- 两终端统一启动Gazebo、RViz、ROS2、Nav2与已有RL，实际关节和TF同步。
- 查询/开启/关闭导航总开关，终端输入x、y、角度或Gazebo选点提交目标。
- Action反馈与结果、手动/导航互斥、停止、取消和输入超时归零。
- 已知地图全局规划；三维雷达过滤地面与自身，实时障碍进入全局/局部costmap。
- MPPI局部避让、有限重规划，Lattice矩形朝向检查，近期失败路段偏好和必要后退。
- RViz区分执行路线与规划预览，显示任务状态，查询最后成功/失败原因。

## 当前系统流程

目标 → mission_manager → ComputePathToPose → Lattice全局路线 → FollowPath → MPPI/RPP
→ /nav_cmd_vel → 运动节点 → UDP速度 → ONNX运动策略 → UDP关节控制 → Gazebo。
雷达 → 感知过滤/短期预测 → costmap → 规划/局部控制；真值状态 → /odom与TF → 任务/导航反馈。
整体仍为六个源码包，插件/包/进程不等于ROS节点，优化没有额外添加常驻节点。

## 汇报时必须说明

- 运行官方预训练策略推理，不代表我们已训练RL。
- 已知障碍规划与雷达检测临时/移动障碍是不同部分，目前两者都接入，但动态场景覆盖有限。
- 当前/odom来自Gazebo真值，不是实际传感器融合定位。
- 当前固定地图，不是SLAM；平地过滤不适用于任意崎岖地形。
- 轮廓/地图离散近似、RL动作误差和腿部外摆仍会影响窄道通行，BLOCKED不等于确认物理碰撞。
- 后续保持原计划，扩大动态场景验证，再接SLAM/地形理解；未实现跌倒恢复和完整训练链。
